## 📚 Key Learnings

### 1. Testing is more than checking whether the app works

A production application must also handle incorrect inputs, API failures, empty states, slow responses, and unexpected user behavior.

### 2. Error handling is part of UX

Instead of allowing an application to fail silently, users should receive clear and useful feedback when something goes wrong.

### 3. Edge cases matter

Testing only the happy path is not enough. Invalid inputs and unexpected scenarios can expose serious bugs.

### 4. Security should be considered before deployment

Configuration, API keys, user input, and error messages should be reviewed before making an application public.

### 5. Performance affects user experience

Reducing unnecessary operations and improving application efficiency helps create a smoother experience.

### 6. Accessibility improves usability

Clear labels, readable interfaces, useful feedback, and responsive layouts make applications easier to use for everyone.

### 7. Release readiness requires an end-to-end mindset

A feature is not truly complete until it works reliably from the user's first interaction through the final expected outcome.
